# chain-proxy — личный VPN-туннель на двух серверах

Этот репозиторий автоматически настраивает **два арендованных сервера** так, чтобы у вас был свой личный VPN-канал с важным свойством:

- Русскоязычные сайты (Яндекс, VK, Mail, Сбер и т. п.) **открываются с IP домашнего сервера** — не банят вас за «вход из-за границы».
- Всё остальное (Google, YouTube, иностранные сервисы) **выходит в интернет через зарубежный сервер** — работает без блокировок.

Вы **один раз** арендуете два сервера, запускаете один скрипт, и дальше пользуетесь. Не нужно ни в чём разбираться — достаточно следовать шагам ниже.

---

## Что вам понадобится

### 1. Два сервера (VPS)

Купите у любого провайдера, рекомендую https://aeza.ru/?ref=468442

| Сервер | Где | Зачем | Минимум |
|--------|-----|-------|---------|
| **VPS1** | **Домашний** (внутри РФ) | «Входной» — к нему подключается ваш телефон/ноутбук | 1 CPU, 1 GB RAM, Ubuntu 24.04 |
| **VPS2** | **Зарубежный** (любая страна вне РФ) | «Выходной» — через него вы выходите в интернет | 1 CPU, 1 GB RAM, Ubuntu 24.04 |

**Важно** при заказе:
- Операционная система: **Ubuntu 24.04**.
- Вам должны прислать **IP-адрес** и **root-пароль** (или дать добавить SSH-ключ).

### 2. Ваш компьютер

- **Mac** или **Linux** — работает из коробки. 
- **Windows** — установите [WSL](https://learn.microsoft.com/ru-ru/windows/wsl/install) (Ubuntu внутри Windows) и дальше работайте в нём.
- Установлены: `git`, `make`, `curl`, `python3` и `Docker`. На Mac: `brew install git make python3` а Docker скачать с оф сайта.

### 3. SSH-ключ

Это «цифровой пропуск» к серверам, надёжнее пароля. Проверьте, есть ли он у вас:

```bash
ls ~/.ssh/id_ed25519.pub
```

Если выводится ошибка «No such file» — создайте:

```bash
ssh-keygen -t ed25519 -C "chain-proxy"
# нажимайте Enter на все вопросы — этого достаточно
```

Затем **добавьте ключ на оба сервера** (команды выполните со своего компьютера):

```bash
ssh-copy-id root@IP_ПЕРВОГО_СЕРВЕРА
ssh-copy-id root@IP_ВТОРОГО_СЕРВЕРА
```

Проверьте доступность

```bash
ssh root@IP_ПЕРВОГО_СЕРВЕРА "echo OK"
ssh root@IP_ВТОРОГО_СЕРВЕРА "echo OK"
```

Должно напечататься `OK`. Если не получилось — разберитесь с этим шагом, дальше идти смысла нет.

### 4. Клиент (приложение на телефоне/ноутбуке)

Выберите одно:

- **[Amnezia](https://amnezia.org)** — самое простое, на русском, для всех ОС.
- **[v2rayN](https://github.com/2dust/v2rayN)** — Windows.
- **[NekoBox](https://github.com/MatsuriDayo/NekoBoxForAndroid)** — Android.
- **[V2Box](https://apps.apple.com/app/v2box-v2ray-client/id6446814690)** — iOS.

Установите заранее — в конце настройки вставите туда готовую ссылку.

## Установка (пошагово)

Откройте терминал (Mac: `Terminal.app`; Windows: Ubuntu WSL) и выполните:

### Шаг 1. Скачайте проект

```bash
git clone <адрес-этого-репозитория> chain-proxy
cd chain-proxy
```

### Шаг 2. Установите Ansible

Ansible — это программа, которая зайдёт на ваши серверы по SSH и выполнит всю настройку. Ставится один раз:

```bash
make install
```

Если команда ругается на отсутствие `pipx` — поставьте его:
- Mac: `brew install pipx`
- Ubuntu/WSL: `sudo apt install pipx && pipx ensurepath`
- Перезапустите терминал и снова `make install`.

### Шаг 3. Укажите IP ваших серверов

```bash
cp .env.example .env
```

Откройте `.env` в любом редакторе (`nano .env` / `code .env`) и впишите **свои** IP-адреса:

```env
IP_VPS1=99.111.10.11      # IP домашнего сервера (VPS1)
IP_VPS2=111.22.155.11     # IP зарубежного сервера (VPS2)
```

Сохраните.

### Шаг 4. Сгенерируйте секретные ключи

Это нужно сделать один раз. Ключи работают как пароли внутри туннеля.

```bash
make gen-keys
```

Команда **сама** допишет нужные ключи в ваш `.env` между строк-маркеров:

```
# === chain-proxy keys (auto-generated by make gen-keys; do not edit) ===
ENTRY_CLIENT_UUID=...
ENTRY_PRIVATE_KEY=...
...
# === end chain-proxy keys ===
```

**Копировать/вставлять ничего не нужно** — при следующих командах Ansible сам прочитает их из `.env`.

В терминал также распечатаются **две готовые VLESS-ссылки** (`vless://...`):
- `#chain-ru-admin` — ваш личный (админский) логин;
- `#chain-ru-friends` — общая ссылка для друзей/семьи.

Сохраните обе — они пригодятся в самом конце, чтобы подключить клиент.

> Повторный запуск `make gen-keys` перезапишет блок с ключами — старая ссылка перестанет работать. Запускайте только если хотите **сбросить** все пароли.

> Если `make gen-keys` ругается «install xray, docker or podman» — поставьте Docker Desktop (Mac/Windows) или `sudo apt install docker.io` (Linux) и запустите команду ещё раз.

### Шаг 5. Проверьте связь с серверами

```bash
make ping
```

Должно вывести два зелёных `SUCCESS`. Если ошибки — вы не добавили SSH-ключ на серверы (вернитесь к «Что вам понадобится», пункт 3).

### Шаг 6. Запустите настройку

```bash
make deploy
```

Это займёт 3–7 минут. Ansible:
- обновит оба сервера,
- установит защитный файрвол,
- поставит программу Xray (это и есть ваш VPN-сервер),
- настроит правила маршрутизации (кто куда идёт),
- запустит сервис.

В конце вы увидите большое сообщение с **двумя готовыми VLESS-ссылками** (admin и friends) и командами для проверки.

### Шаг 7. Подключите клиент

Откройте выбранное приложение (Amnezia / v2rayN / NekoBox):
- **Amnezia:** «+ → Импорт из строки подключения» → вставьте `vless://...`.
- **v2rayN:** «Servers → Import from clipboard» (предварительно скопировав ссылку).
- **NekoBox / V2Box:** «+ → Импортировать из буфера обмена».

Включите подключение. Всё.

## Как проверить, что всё работает

С устройства, где **включен** клиент, в браузере откройте:

| Адрес | Что должно произойти |
|-------|----------------------|
| https://api.ipify.org | Показать IP **вашего** зарубежного сервера (VPS2) |
| https://www.google.com | Открыться без капч и ограничений |
| https://yandex.ru | Открыться нормально, как из России |
| https://mail.ru | Войти без «вход из новой страны» |

Если с командной строки:

```bash
curl -s https://api.ipify.org          # → ваш IP_VPS2
curl -sI https://yandex.ru | head -n 1 # → HTTP/2 200
curl -sI https://www.google.com | head -n 1
```

**Главное доказательство работы схемы:** российские сайты видят вас с IP домашнего сервера, а Google и прочее — с IP зарубежного сервера. Никто не в курсе, что трафик разделяется.

## Объяснение переменных простыми словами

### Файл `.env` (в корне проекта)

| Переменная | Что это | Пример |
|------------|---------|--------|
| `IP_VPS1` | IP-адрес **домашнего** сервера. Выдаётся хостером после покупки. | `99.111.10.11` |
| `IP_VPS2` | IP-адрес **зарубежного** сервера. | `111.22.155.11` |

### Файл `ansible/group_vars/all.yml` — общие настройки

| Переменная | Что это | Когда трогать |
|------------|---------|---------------|
| `reality_dest_host` | «Маскировочный» сайт, под который ваш VPN притворяется (по умолчанию `www.microsoft.com`). Помогает проходить глубокую инспекцию трафика. | Обычно не трогать. Если Microsoft заблокируют — поменять на `www.apple.com` или `www.cloudflare.com`. |
| `geodata_update_enabled` | Автообновление списков «какие IP российские». | Оставить `true`. |
| `firewall_allowed_tcp_ports` | Какие порты открыты наружу. | Оставить как есть. |

### Секреты (VPS1 и VPS2) — всё в `.env`, автоматически

Ключи и UUID живут в том же файле `.env`, в блоке между маркерами:

```
# === chain-proxy keys (auto-generated by make gen-keys; do not edit) ===
ENTRY_CLIENT_UUID=...      # admin
ENTRY_FRIENDS_UUID=...     # общий «логин» для друзей
ENTRY_PRIVATE_KEY=...
ENTRY_PUBLIC_KEY=...
ENTRY_SHORT_ID=...
LINK_UUID=...
LINK_PUBLIC_KEY=...
LINK_PRIVATE_KEY=...
LINK_SHORT_ID=...
# === end chain-proxy keys ===
```

Что означает каждая переменная:

| Переменная | Что это |
|------------|---------|
| `ENTRY_CLIENT_UUID` | Ваш личный (админский) «логин» при подключении к VPS1. |
| `ENTRY_FRIENDS_UUID` | Общий «логин» для друзей/семьи. Можно раздавать без опаски — ключи Reality (`pbk`/`sid`) у обеих ссылок одинаковые, но UUID разный, и при необходимости его легко отозвать (см. ниже). |
| `ENTRY_PRIVATE_KEY` / `ENTRY_PUBLIC_KEY` | Пара ключей шифрования **клиент ↔ VPS1**. Public уезжает в клиент, private остаётся на VPS1. |
| `ENTRY_SHORT_ID` | Метка сессии для входа. |
| `LINK_UUID` | «Логин» для внутреннего соединения **VPS1 → VPS2**. |
| `LINK_PUBLIC_KEY` / `LINK_PRIVATE_KEY` | Пара ключей шифрования **VPS1 ↔ VPS2**. Public нужен на VPS1, private — на VPS2. |
| `LINK_SHORT_ID` | Метка сессии для межсерверного линка. |

**Главное:** все эти переменные генерирует `make gen-keys`, трогать вручную не нужно. Файлы в `ansible/group_vars/` уже настроены на чтение из окружения — вы их не редактируете никогда.

## Команды Makefile (шпаргалка)

Все команды запускайте из корня проекта.

### Первичная настройка

| Команда | Что делает |
|---------|-----------|
| `make install` | Ставит Ansible на ваш компьютер. Один раз. |
| `make gen-keys` | Генерирует ключи и UUID. Запустите один раз перед первым деплоем. |

### Проверка перед запуском

| Команда | Что делает |
|---------|-----------|
| `make ping` | Проверяет, что серверы доступны по SSH. |
| `make syntax` | Проверяет, что плейбук без синтаксических ошибок. |
| `make check` | **«Сухой прогон»** — показывает, что *будет* сделано, но ничего не меняет. Полезно перед реальным `deploy`. |

### Запуск и обновление

| Команда | Что делает |
|---------|-----------|
| `make deploy` | Настраивает **оба** сервера с нуля или накатывает изменения. Безопасно запускать повторно. |
| `make deploy-entry` | Настроить только VPS1 (домашний). |
| `make deploy-exit` | Настроить только VPS2 (зарубежный). |

### Повседневная работа

| Команда | Что делает |
|---------|-----------|
| `make status` | Показать состояние VPN-сервиса на обоих серверах (running / failed). |
| `make logs` | Последние 50 строк лога с каждого сервера. |
| `make restart` | Перезапустить VPN-сервис (если что-то «подвисло»). |
| `make reload` | То же, но без разрыва соединений. |
| `make xray-test` | Проверить, что конфиг на серверах валидный. |
| `make tail-entry` / `tail-exit` | «Живой» лог конкретного сервера. |

Подсказка: просто `make` (без аргументов) выведет весь список.

## Если что-то пошло не так

| Симптом | Что проверить |
|---------|---------------|
| `make ping` ругается `UNREACHABLE` | SSH-ключ не добавлен на сервер (шаг 3). Попробуйте `ssh root@<IP>` вручную. |
| `make deploy` падает на `Validate required variables` | В `.env` нет блока с ключами — запустите `make gen-keys`. Или переменные не экспортировались: убедитесь, что запускаете именно `make` (а не `ansible-playbook` напрямую). |
| Клиент подключается, но сайты не открываются | 1) `make status` — сервис должен быть `active (running)` на обоих. 2) Проверьте часы: `ansible -i ansible/inventory.yml all -b -a 'date'` — если разница больше 30 сек, Reality не работает. |
| Google открывается, а Яндекс — нет (или наоборот) | `make logs` — посмотреть ошибки. Убедитесь, что geodata подгрузилась: `ansible -i ansible/inventory.yml all -b -a 'ls -la /usr/local/share/xray/'`. |
| Клиент вообще не коннектится | Пересоздайте ключи: `make gen-keys` (перезапишет блок в `.env`) → `make deploy` → новая VLESS-ссылка в клиент. |

Подробный лог последнего запуска: `make logs` или прямо на сервере `journalctl -u xray -f`.

## Архитектура (для любопытных)

```
  Ваш телефон/ноутбук (клиент)
       │    зашифровано по протоколу VLESS + Reality
       ▼
  ┌──────────────┐   Если сайт российский → выход в интернет ПРЯМО с VPS1 (домашний IP)
  │ VPS1 (домашний) │─▶ Если локальная сеть  → заблокировано
  │   вход       │   Всё остальное        → шифруется ещё раз и уходит на VPS2
  └──────┬───────┘
         │ зашифровано по тому же VLESS + Reality
         ▼
  ┌──────────────────┐
  │ VPS2 (зарубежный) │─▶ выход в интернет (зарубежный IP)
  │   выход          │
  └──────────────────┘
```

**Почему двух серверов достаточно:**
- Один домашний нужен, чтобы Яндекс/Mail/Госуслуги видели «нормального пользователя из России».
- Один зарубежный нужен, чтобы Google/YouTube/etc работали без ограничений.
- Правило «кто куда» написано на VPS1 и обновляется автоматически (geodata раз в неделю).

**Что такое VLESS + Reality:** современный протокол, при котором ваш VPN снаружи выглядит как обычный поход на `www.microsoft.com`. Провайдер / DPI не может отличить и не блокирует.

## Расширение

Когда всё работает и хочется большего:

- **AmneziaWG fallback** на VPS1 — добавьте роль `roles/amneziawg/` на ту же точку входа; Xray слушает 443/tcp, WireGuard — UDP, не конфликтуют.
- **Свой SNI** (под что маскируемся) — `reality_dest_host` в `group_vars/all.yml`.
- **Приватный линк между VPS** — переопределите `exit_address` в `entry.yml` на внутренний IP (VPC / приватная сеть у хостера).

## Управление пользователями (admin / friends / ещё)

«Из коробки» уже есть **два логина**: `admin` (для вас) и `friends` (общая ссылка для друзей). У каждого свой UUID, но Reality-ключи (`pbk`, `sid`) общие — на стороне сервера это **разные клиенты в одном inbound**. Это значит:

- ссылку `friends` можно безопасно раздавать — она никак не выдаёт ваш `admin`-UUID;
- если друзей нужно «отключить» — меняется только `ENTRY_FRIENDS_UUID`, ваш `admin` остаётся прежним;
- чтобы отличать пользователей в логах, в конфиге у каждого проставлен `email` (`admin` / `friends`) — он же подставляется в имя ссылки (`#chain-ru-admin`, `#chain-ru-friends`).

### Где это лежит

Список клиентов входного inbound описан в [`ansible/group_vars/entry.yml`](ansible/group_vars/entry.yml):

```yaml
entry_clients:
  - email: "admin"
    id: "{{ lookup('env', 'ENTRY_CLIENT_UUID') }}"
  - email: "friends"
    id: "{{ lookup('env', 'ENTRY_FRIENDS_UUID') }}"
```

Шаблон [`ansible/roles/xray_entry/templates/config.json.j2`](ansible/roles/xray_entry/templates/config.json.j2) проходит по этому списку и собирает `clients` для Xray. Ссылки на каждого пользователя печатает плейбук в конце `make deploy`.

### Где взять ссылку для друга

Самый простой путь — после `make deploy` пролистать вывод вверх и найти строку:

```
[friends]  vless://...#chain-ru-friends
```

Это и есть готовая ссылка. Либо отдельно — пересоздать ключи `make gen-keys` (он распечатает обе ссылки в самом конце).

### Сменить UUID для друзей (если ссылка «утекла»)

Не трогая `admin`:

```bash
# 1. Сгенерировать новый UUID
NEW_FRIENDS_UUID=$(uuidgen | tr '[:upper:]' '[:lower:]')

# 2. Заменить только ENTRY_FRIENDS_UUID в .env
sed -i.bak "s/^ENTRY_FRIENDS_UUID=.*/ENTRY_FRIENDS_UUID=$NEW_FRIENDS_UUID/" .env && rm .env.bak

# 3. Раскатить обновлённый конфиг (только VPS1, его достаточно — на VPS2 клиентов нет)
make deploy-entry
```

Старая ссылка для друзей перестанет работать сразу. Ваша `admin`-ссылка не затрагивается.

> Если запустить `make gen-keys`, он перегенерирует **весь** блок ключей в `.env` (и admin, и friends, и Reality-ключи). После этого старые ссылки умрут у обоих — используйте только когда хотите полный сброс.

### Полностью отключить друзей

Удалите запись `friends` из списка `entry_clients` в [`ansible/group_vars/entry.yml`](ansible/group_vars/entry.yml) и запустите `make deploy-entry`. Переменная `ENTRY_FRIENDS_UUID` в `.env` не помешает — её просто никто не будет читать.

### Добавить третьего пользователя (например, для работы)

Допустим, нужна ещё одна отдельная ссылка с тегом `work`:

1. Придумать имя env-переменной — например, `ENTRY_WORK_UUID`.
2. Дописать запись в [`ansible/group_vars/entry.yml`](ansible/group_vars/entry.yml):

   ```yaml
   entry_clients:
     - email: "admin"
       id: "{{ lookup('env', 'ENTRY_CLIENT_UUID') }}"
     - email: "friends"
       id: "{{ lookup('env', 'ENTRY_FRIENDS_UUID') }}"
     - email: "work"
       id: "{{ lookup('env', 'ENTRY_WORK_UUID') }}"
   ```

3. Добавить переменную в `export` в [`Makefile`](Makefile) (рядом с `ENTRY_FRIENDS_UUID`):

   ```make
   export ENTRY_CLIENT_UUID ENTRY_FRIENDS_UUID ENTRY_WORK_UUID ENTRY_PRIVATE_KEY ENTRY_PUBLIC_KEY ENTRY_SHORT_ID
   ```

4. Сгенерировать UUID и дописать его в `.env` рядом с остальными:

   ```bash
   echo "ENTRY_WORK_UUID=$(uuidgen | tr '[:upper:]' '[:lower:]')" >> .env
   ```

5. `make deploy-entry`. Плейбук распечатает уже **три** VLESS-ссылки (`#chain-ru-admin`, `#chain-ru-friends`, `#chain-ru-work`).

> Никаких новых Reality-ключей генерировать не нужно — все клиенты делят один серверный keypair и один shortId. Каждый пользователь — это просто отдельный UUID в массиве `clients`.

chain-proxy/
├── .env                    # ← всё, что вы редактируете: IP двух VPS + блок ключей

├── Makefile                #   все команды (подхватывает .env автоматически)
